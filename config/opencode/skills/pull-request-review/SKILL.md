# Pull request review

1. Read the PR description and linked ticket; ignore drive-by scope.
2. Walk the diff for correctness bugs first, then tests, then style.
3. Flag security and data-loss risks explicitly.
4. Keep comments actionable; prefer suggested patches for small issues.
5. End with a clear ship / request-changes recommendation.
